# Умный кредитный кабинет предпринимателя

Прототип цифрового кредитного конвейера для малого и микробизнеса (Альфа-Хакатон): **личный кабинет клиента** и **рабочее место банка** в одном продукте. Заявка проходит весь путь внутри системы: выбор продукта → заявка → проверка данных → запросы в источники → скоринг → кредитное решение (одобрение / встречное предложение / запрос информации / отказ / ручное рассмотрение) → оферта → подписание → выдача. ИИ/LLM не используются.

## Быстрый старт

Требования: Docker 24+ и Docker Compose v2, свободный порт 8000. Больше ничего (сеть, платные сервисы, ключи не нужны).

```bash
git clone <repo-url> && cd alfa-credit-cabinet
docker compose up --build
# откройте http://localhost:8000      (Swagger UI: /docs, OpenAPI: /openapi.json, health: /health)
```

Без Docker (Python 3.12): `python -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt && uvicorn app.main:app --port 8000`.

**Тесты:** `pip install -r requirements-dev.txt && PIPELINE_SYNC=1 python -m pytest -q` (10 сквозных тестов).

## Тестовые учётные записи (пароль у всех `Demo#2026`)
| Логин | Роль |
|---|---|
| `client1`, `client2`, `client3` | клиент (предприниматель) |
| `underwriter` | сотрудник банка (андеррайтер) |

Синтетические компании и ИНН для всех веток процесса — в [docs/TEST_SCENARIOS.md](docs/TEST_SCENARIOS.md); их также можно выбрать прямо в форме заявки («Тестовые ИНН»). Аккаунты создаются при первом старте (`app/seed.py`), данные компаний — в симуляторах (`app/integrations.py`).

## Пошаговая проверка основного сценария (≈3 мин)
1. Войдите как `client1` → **Новая заявка** → «Оборотный кредит», сумма 1 200 000 ₽, срок 24 мес., цель — любая.
2. Шаг «Компания»: выберите тестовый ИНН `7701000019` → **Найти в реестре** → роль «Собственник».
3. Шаг «Финансы»: выручка `24000000`, прибыль `3600000`, платежи `40000`. Шаг «Проверка» → согласие → **Отправить в банк**.
4. Статус меняется сам (проверка данных → источники → оценка риска → «Предложение готово»). Нажмите **Принять предложение** → **Подписать договор** → «Деньги выданы» (график платежей).
5. Ветка банка: от `client3` подайте заявку по сценарию 3 из TEST_SCENARIOS (ИНН `7701000033`, оборудование 4 млн, приложите любой файл как «Бухгалтерская отчётность»). Войдите как `underwriter` → заявка в «На рассмотрении андеррайтера» → данные ЕГРЮЛ/ФНС/БКИ, разбор скоринга → решение (одобрить / другие условия / запросить информацию / отказать). Клиент увидит результат без перезагрузки страницы.
6. Данные сохраняются в томе `creditdata` (переживают перезапуск): `docker compose down` не удаляет их, `docker compose down -v` сбрасывает.

## Архитектура
FastAPI (REST + раздача SPA) → сервисный слой (автомат состояний, аудит) → чистый домен (валидация, скоринг, решение) → SQLite (WAL); кредитный конвейер — фоновый поток, внешние сервисы — симуляторы. Подробно, с диаграммами, моделью данных и обоснованием MVP: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Конфигурация (переменные окружения)
| Переменная | По умолчанию | Назначение |
|---|---|---|
| `JWT_SECRET` | демо-значение | ключ подписи токенов — **переопределить вне демо** (см. `.env.example`) |
| `TOKEN_TTL_HOURS` | `8` | срок жизни токена |
| `PIPELINE_STEP_DELAY` | `1.0` | пауза между этапами конвейера, сек (чтобы этапы были видны в UI; `0` — мгновенно) |
| `PIPELINE_SYNC` | `0` | `1` — конвейер выполняется синхронно (для тестов) |
| `DB_PATH` | `/data/credit.db` в Docker | путь к файлу БД |

## Основные допущения
Скоринг и правила решения упрощены и явно описаны (ARCHITECTURE.md §5); подпись, выдача, загрузка документов и внешние реестры смоделированы (THIRD_PARTY_NOTICES.md); весь пользовательский путь проходит внутри продукта — без почты, SMS и мессенджеров; клиентская часть — веб-интерфейс.
